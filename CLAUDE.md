## Aperçu du projet

JOEM ("Job Offer & Employment Madagascar") est une application Flutter ciblant le marché de l'emploi malgache, mettant en relation recruteurs et chercheurs d'emploi. Le flux complet onboarding → inscription → connexion → dashboard est câblé de bout en bout, avec une vraie persistance locale (SQLite via `sqflite`/`sqflite_common_ffi`, voir `lib/core/database/app_database.dart` — comptes, offres, candidatures, notifications, historique de recherche : plus un simple mock en mémoire). Pas de state management (pas de provider/riverpod/bloc), pas de routeur déclaratif — uniquement `Navigator.push`/`pushReplacement`. Une seule paire de dashboards existe désormais (l'ancienne branche parallèle non branchée a été supprimée, voir plus bas). L'app reste presque entièrement locale, à une exception près : la connexion/inscription via Google (`GoogleAuthService`, package `google_sign_in`) contacte réellement les serveurs Google — c'est la seule fonctionnalité réseau de toute l'app, tout le reste (comptes, offres, candidatures, notifications, recherche...) reste 100% SQLite sur l'appareil. Côté recruteur, tout le dashboard est désormais réel (offres, candidatures par offre, vues, entretiens — tables `job_offer_views` et `interviews` ajoutées) ; côté candidat, l'accueil ne contient plus aucune donnée mockée (les anciens blocs "Statistiques perso"/"Mes prochains entretiens" ont été retirés de l'accueil — les statistiques réelles vivent dans le panneau latéral `ProfileSidePanel`, les entretiens dans `MyInterviewsScreen`/notifications). Un "Mode nuit"/"Texte agrandi"/"Animations réduites" global existe (`DisplayPreferencesController` + extension de thème `AppSurfaceColors`, voir "Point d'entrée"). L'ancien onglet "Publier" du candidat (composeur de post social mocké, jamais persisté, sans aucun public pour le lire) a été remplacé par un vrai portfolio multi-écrans (`PortfolioScreen` en écran principal + `PortfolioAboutScreen`/`PortfolioSkillsScreen`/`PortfolioExperienceScreen`/`PortfolioProjectsScreen`/`PortfolioProjectDetailScreen`/`PortfolioCertificationsScreen`) : identité, "À propos"/"Mes objectifs"/"Mes liens", compétences, expérience professionnelle + formations, projets réalisés (avec détail par projet : rôle, technologies, fonctionnalités, liens GitHub/démo) et certifications — réellement persistés (tables `job_seeker_portfolio_projects` étendue, `job_seeker_formations`, `job_seeker_certifications`, `job_seeker_professional_links`, colonne `job_seeker_profiles.objectifs`) et visibles par les recruteurs sur `CandidateProfileViewScreen` — voir "Ce qu'on trouve dans les dashboards" et "Ce qui a changé récemment".

## Commandes

```bash
flutter pub get                     # installer les dépendances
flutter run                         # lancer sur un appareil/émulateur connecté
flutter run -d chrome                # lancer dans un navigateur (la cible web est configurée)
flutter test                        # lancer tous les tests
flutter test test/widget_test.dart  # lancer un seul fichier de test
flutter test --plain-name "Welcome screen loads"  # lancer un seul test par son nom
flutter analyze                     # analyse statique (utilise flutter_lints, voir analysis_options.yaml)
flutter build apk / ios / web       # builds par plateforme
```

Il n'y a pas de configuration CI, pas de règles de lint personnalisées au-delà de l'ensemble par défaut `flutter_lints`, et pas d'étape de génération de code (pas de `build_runner`). `pubspec.yaml` déclare, en plus de `cupertino_icons`/`google_fonts` : `image_picker` (photo de couverture/profil/logo — désormais toutes les deux persistées, voir plus bas), `file_picker`/`open_file` (CV), `sqflite`/`sqflite_common_ffi`/`sqflite_common_ffi_web`/`sqlite3_flutter_libs`/`path`/`path_provider`/`crypto` — la vraie base SQLite locale (`lib/core/database/app_database.dart`, un seul fichier `joem.db`, schéma version 30, migrations versionnées dans `onUpgrade`) qui persiste comptes, offres, candidatures, notifications, historique de recherche et portfolio candidat — `google_sign_in` (v7, API Credential Manager) pour la connexion/inscription Google réelle (`lib/core/services/google_auth_service.dart`), et `url_launcher` (composeur `tel:` / client mail `mailto:` — coordonnées cliquables du candidat dans `CandidateApplicationDetailScreen`). Aucune lib de state management (provider/riverpod/bloc) ni de routeur (go_router) n'a été ajoutée. En dev dependency : `flutter_launcher_icons` génère l'icône d'app de toutes les plateformes depuis `assets/images/joem-apk-logo.png` (section `flutter_launcher_icons` du `pubspec.yaml`, régénérer avec `dart run flutter_launcher_icons` — c'est ce qui a produit les icônes modifiées sous `android/…/mipmap-*`, `ios/…/AppIcon.appiconset`, `web/icons`, `macos/…`, `windows/runner/resources`). `image_picker` nécessite les entrées `NSCameraUsageDescription`/`NSPhotoLibraryUsageDescription` dans `ios/Runner/Info.plist` (déjà ajoutées) ; Android nécessite la permission `INTERNET` dans `AndroidManifest.xml` (ajoutée avec Google Sign-In) et deux `<intent>` dans `<queries>` pour `url_launcher` (`DIAL` scheme `tel`, `SENDTO` scheme `mailto`).

**Config Google Sign-In requise avant de tester la connexion Google** : `lib/core/constants/google_config.dart` contient un `kGoogleServerClientId` placeholder (`'REMPLACE_MOI.apps.googleusercontent.com'`) à remplacer par le Client ID d'un client OAuth "Web application" créé sur Google Cloud Console, dans le même projet qu'un client OAuth "Android" (package `com.example.joem` + SHA-1 de signature). Sans ça, `GoogleAuthService.signIn()` échoue avec une `GoogleSignInException` de configuration. Voir le code de `google_auth_service.dart` pour le détail du flux (API `GoogleSignIn.instance`, pas l'ancienne API `GoogleSignIn()`).

**Problème d'environnement connu (Android)** : `flutter build apk`/`flutter run` sur Android échoue actuellement dans cet environnement avec `Error when reading '/main.dart'` pendant la tâche Gradle `compileFlutterBuildDebug` — confirmé pré-existant (reproductible même sur un `git stash` complet, donc indépendant de tout changement applicatif récent). À diagnostiquer séparément (config Gradle/Windows) avant de pouvoir tester Google Sign-In ou toute autre fonctionnalité sur un vrai appareil/émulateur Android depuis cette machine. `flutter build web` et `flutter analyze`/`flutter test`, eux, fonctionnent normalement (dernier état vérifié : `flutter analyze` → 0 erreur/0 warning, ~31 `info` surtout `withOpacity` déprécié ; `flutter test` → vert).

**Note tests** : `flutter test` sans argument ne lance que les fichiers suffixés `_test.dart` (aujourd'hui 32 tests : `widget_test`, `job_seeker_home_test`, `onboarding_screens_smoke_test`, `candidate_application_portfolio_test`, `job_offer_categories_test`, `application_rejection_test`, `interview_to_be_defined_test`, `reject_dialog_test`, `candidate_screens_smoke_test` — tous verts). Préférer `flutter test --timeout 120s` : un test widget mal écrit peut sembler bloqué au lieu d'échouer (voir "Rejet d'une candidature"). Les fichiers `test/_tmp_*.dart` (scratch : `_tmp_recruiter_login_check`, `_tmp_employer_application_notification_check`, `_tmp_job_offer_visibility_check`, `_tmp_splash_check`) ne tournent que si on les passe explicitement en chemin.

## Architecture

Le code suit une structure **feature-first** sous `lib/` :

- `lib/core/` — briques partagées entre toutes les fonctionnalités :
  - `theme/` — tokens de design : `app_colors.dart`, `app_spacing.dart`, `app_durations.dart`, `app_shadows.dart`, `app_radius.dart`, `app_typography.dart` (échelles Poppins/Inter via Google Fonts — fusion de l'ancien `app_text_styles.dart`, supprimé), `app_surface_colors.dart` (`AppSurfaceColors`, `ThemeExtension` clair/sombre — fond de page/cartes/textes/séparateurs lus via `AppSurfaceColors.of(context)` ; la variante `light` reprend exactement les valeurs `AppColors`, donc migrer un écran de `AppColors.x` vers `AppSurfaceColors.of(context).x` ne change rien hors mode nuit), et `app_theme.dart` (le `ThemeData` Material 3 global, toujours *non* appliqué — voir ci-dessous). Les anciens doublons `app_radii.dart` et `app_text_styles.dart` ont été supprimés/fusionnés dans `app_radius.dart`/`app_typography.dart` : un seul fichier par token désormais.
  - `widgets/` — composants partagés : `glass_container.dart`/`glass_button.dart` (verre dépoli — `GlassButton` accepte un paramètre optionnel `color` pour surcharger le mauve `AppColors.primary` par défaut ; login et les wizards d'inscription lui passent `OnboardingColors.violet`), le kit de formulaire clair (`form_surface.dart`, `light_text_field.dart`, `light_dropdown.dart`, `joem_gradient_logo.dart`, `google_sign_in_button.dart`, `or_divider.dart`), le kit d'inscription en wizard (`registration_stepper.dart`, `wizard_navigation.dart`, `step_one_account.dart` — désormais un `StatefulWidget` qui déclenche une vraie authentification Google au tap, voir plus bas), `notification_badge.dart` (pastille rouge de compteur style Facebook, réutilisée par les headers et les nav basses des deux dashboards), `location_autocomplete_field.dart` (autocomplétion sur `kMalagasyCities`), `animated_entrance.dart` (`FadeSlideIn` — apparition en fondu + glissement avec délai, pour échelonner les éléments d'une liste une fois les données chargées ; rejoue quand la `key` change), `skeleton_loading.dart` (`ShimmerLoading` + `SkeletonBox` — squelettes "shimmer" des états de chargement ; ces deux derniers sont utilisés par les deux dashboards, les écrans de notifications, de recherche, `CategoryOffersScreen` et `EmployerOffersScreen`) et `profile_photo_viewer_screen.dart` (`ProfilePhotoViewerScreen` — visionneuse plein écran zoomable d'une photo, partagée par `JobProfileScreen` et `ProfileSidePanel`). Le "kit dashboard" (`dashboard_card.dart`, `section_header.dart`, `advice_card.dart`, `mini_line_chart_painter.dart`) a été supprimé : il n'était utilisé que par la branche dashboard non branchée, elle-même supprimée (voir "Ce qui a changé récemment"). `centered_logo.dart` (ancien wordmark en image PNG) a lui aussi été supprimé ; `joem_gradient_logo.dart` (`JoemGradientLogo`) le remplace partout — un texte "JOEM" au dégradé navy→violet (`ShaderMask` + Google Fonts Poppins), même identité que le bloc de marque du welcome screen.
  - `services/auth_service.dart` — service d'authentification utilisé par l'écran de connexion et les dashboards : 2 comptes de démo en dur (`employeur@gmail.com` / `candidat@gmail.com`, id négatif, aucune ligne dans `users`) + tout compte réellement inscrit (lu depuis SQLite). Méthodes `login()`, `logout()`, `restoreSession()` (reconnexion auto au démarrage), `isEmployer()`, `isJobSeeker()`, `setSession()` (ouvre une session juste après inscription), `loginWithGoogle()` (connecte un compte JOEM existant dont l'email correspond à celui du compte Google authentifié — ne crée jamais de compte, renvoie `null` si annulé par l'utilisateur ou `false` si aucun compte JOEM ne correspond), `resetPassword()` (réinitialisation locale du mot de passe par email, utilisée par `ForgotPasswordScreen` — pas de comptes de démo), `updateProfilePhoto`/`updateCoverPhoto`/`updateCv`/`updateJobSeekerProfile`(accepte désormais `objectifs`)/`updateEmployerProfile`/`addExperience`/`deleteExperienceAt` (persistent les modifications faites depuis `JobProfileScreen`/`EmployerProfileScreen` et leurs écrans "Modifier le profil"), et — pour le Portfolio multi-écrans — `addPortfolioProject`(accepte désormais `role`/`technologies`/`features`/`githubLink`/`demoLink` en plus de `title`/`description`/`link`/`imageBytes`)/`deletePortfolioProjectAt`, `addFormation`/`deleteFormationAt`, `addCertification`/`deleteCertificationAt`, `addProfessionalLink`/`deleteProfessionalLinkAt`. `User.portfolioSections`/`portfolioCompletion` calculent le % "Votre portfolio est complété à N %" de `PortfolioScreen` à partir de 6 sections (Présentation/Compétences/Expériences/Projets/Certifications/Liens professionnels).
  - `services/google_auth_service.dart` — fin enrobage de `GoogleSignIn.instance` (package `google_sign_in` v7, API Credential Manager sur Android) : `signIn()` ouvre le sélecteur de compte Google et renvoie un `GoogleSignInAccount?` (email/nom/photo), utilisé à la fois par `AuthService.loginWithGoogle()` (connexion) et `StepOneAccount` (inscription, préremplit email/nom/prénom).
  - `database/app_database.dart` — base SQLite locale unique (`joem.db`, schéma version 30, migrations versionnées dans `onUpgrade`, `sqflite`/`sqflite_common_ffi` selon la plateforme). Toutes les données réelles de l'app (comptes, offres, candidatures, notifications, historique de recherche, portfolio candidat) y vivent — voir "Ce qui est déjà fait" pour le détail par repository. Migration v13→v14 : ajout de `cover_photo` (BLOB) sur `job_seeker_profiles` et `employer_profiles` pour persister la photo de couverture du profil (auparavant perdue à chaque fermeture d'écran). Migrations v22→v23 : colonnes de réglages `EmployerSettingsScreen` sur `employer_profiles` — v22 `notifications_actives`/`entreprise_visible`/`publicite_personnalisee`/`communications_marketing`, v23 `mode_nuit`/`texte_agrandi`/`animations_reduites` (section "Affichage", miroir de `job_seeker_profiles`). Migration v23→v24 : table `job_seeker_profile_views` (une ligne par recruteur distinct qui ouvre `CandidateProfileViewScreen`, `UNIQUE(profile_user_id, viewer_user_id)`) — alimente le compteur "N vues du profil" de `JobProfileScreen`. Migration v24→v25 : table `job_seeker_portfolio_projects` (`user_id` INTEGER FK vers `users`, `title`/`description`/`link`/`image` BLOB/`created_at`) — projets ajoutés par le candidat depuis le Portfolio (`AuthService.addPortfolioProject`/`deletePortfolioProjectAt`), remplace l'ancien onglet "Publier" (composeur de post social mocké). Migration v25→v26 (refonte du Portfolio en plusieurs sous-écrans, voir plus bas) : `job_seeker_profiles.objectifs` (bloc "Mes objectifs") ; `job_seeker_portfolio_projects` gagne `role`/`technologies`/`features`/`github_link`/`demo_link` (facultatifs, pour `PortfolioProjectDetailScreen` — pas de galerie multi-images, une seule image de couverture par projet comme avant) ; nouvelles tables `job_seeker_formations` (`etablissement`/`filiere`/`date_debut`/`date_fin`, section "Parcours" de `PortfolioExperienceScreen`), `job_seeker_certifications` (`name`/`organism`/`date`/`image` BLOB/`verification_link`) et `job_seeker_professional_links` (`label`/`url` — pas de type stocké, l'icône affichée est déduite du domaine de l'URL).
  - `constants/` — listes de référence partagées : `malagasy_cities.dart` (autocomplétion de localisation), `job_categories.dart` (`kJobCategories`, les 24 secteurs proposés à l'inscription recruteur et réutilisés pour filtrer les offres côté candidat), et `google_config.dart` (`kGoogleServerClientId`, à remplacer par un vrai Client ID OAuth avant de tester la connexion Google — voir "Commandes").
  - `services/display_preferences_controller.dart` — `DisplayPreferencesController.instance`, singleton `ChangeNotifier` (mode nuit / texte agrandi ×1.15 / animations réduites) écouté par `JOEMApp` ; simple miroir en mémoire des colonnes `mode_nuit`/`texte_agrandi`/`animations_reduites` (`job_seeker_profiles` et `employer_profiles`), remis à zéro à la déconnexion/suppression de compte.
  - `navigation/` — `app_route_observer.dart` (`appRouteObserver`, `RouteObserver` global enregistré sur `MaterialApp` ; les deux dashboards sont `RouteAware` et rechargent leurs données dans `didPopNext`, même après des retours en plusieurs sauts) et `fade_through_page_transitions_builder.dart` (transition globale fondu + léger glissement vers le haut, appliquée à tous les `MaterialPageRoute` via `pageTransitionsTheme`, sans toucher aux appels `Navigator.push`).
  - `utils/` — `responsive.dart` (breakpoints `isTablet`/`isDesktop`), `password_hasher.dart` (hash des mots de passe, `crypto`), `cv_storage.dart` (copie du CV sur disque, pas en BLOB).
- `lib/features/<feature>/` — chaque fonctionnalité possède ses écrans sous `presentation/` (sous-dossier `widgets/` pour les composants propres à l'écran) et, le cas échéant, ses repositories SQLite sous `data/` (`recruiter_registration/data/recruiter_repository.dart`, `job_seeker_registration/data/job_seeker_repository.dart`, `dashboard/data/{job_offer,account_search,interview}_repository.dart`). Fonctionnalités existantes : `splash/`, `welcome/`, `recruiter_registration/`, `job_seeker_registration/`, `login/` (dont `forgot_password_screen.dart`, voir plus bas), `dashboard/`.

Convention d'imports : dans les widgets propres à une fonctionnalité, les imports relatifs vers `core` sont parfois utilisés (ex. `../../../../core/theme/app_colors.dart`), parfois la forme absolue `package:joem/...` — les deux styles coexistent selon le fichier/la session qui l'a écrit ; jamais harmonisé.

### Point d'entrée et incohérence de thème

`lib/main.dart` : `JOEMApp` est un `StatefulWidget` abonné à `DisplayPreferencesController`. Il construit toujours son `ThemeData` **inline** via `_buildTheme(AppSurfaceColors)` (Material 3, `colorScheme` dérivé du `seedColor` mauve en `Brightness.dark`, coins arrondis 30 des boutons/cartes, splash/highlight transparents, `pageTransitionsTheme` = `FadeThroughPageTransitionsBuilder` sur toutes les plateformes) — une fois avec `AppSurfaceColors.light` (`theme`) et une fois avec `AppSurfaceColors.dark` (`darkTheme`), seule l'extension diffère ; `themeMode` suit `isDarkMode`. Un `builder` multiplie le `textScaler` global par 1.15 quand "Texte agrandi" est actif. `navigatorObservers: [appRouteObserver]`. `home` = `SplashScreen` (`lib/features/splash/`, ~2,3 s, tente `AuthService.restoreSession()` puis `pushReplacement` vers le bon dashboard ou `WelcomeScreen`). Il n'utilise toujours pas `AppTheme.dark` défini dans `lib/core/theme/app_theme.dart`. Remplacer ce thème inline par `AppTheme.dark` a été délibérément écarté (pas juste "pas encore fait") : `AppTheme.dark` n'a pas ces personnalisations, le switch ferait donc régresser visuellement les boutons/cartes/splash pour un gain purement cosmétique — à ne faire que si `AppTheme.dark` est d'abord complété pour matcher l'existant.

Les deux wizards d'inscription créent un vrai compte utilisable, que ce soit par email/mot de passe ou via Google : `LoginScreen` accepte aussi bien les comptes de démo codés en dur dans `AuthService` qu'un compte inscrit via `RecruiterRegistrationScreen`/`JobSeekerRegistrationScreen` (persisté en SQLite) — s'inscrire puis se reconnecter (au clavier ou via Google si l'inscription s'est faite via Google) fonctionne. Un compte créé via Google n'a pas de mot de passe connu de l'utilisateur (un mot de passe aléatoire est généré côté serveur) : `AuthService.resetPassword` (via `ForgotPasswordScreen`) reste le seul moyen d'en obtenir un s'il veut un accès classique en secours.

`BottomNavigation` (partagée par les deux dashboards) est une barre custom (capsule flottante "sculptée" par `CustomClipper`/`CustomPainter` autour d'un bouton "Accueil" rond central, index 0) — pas une `BottomNavigationBar` Material. Items : 0 Accueil (bouton central), 1 = `secondItemLabel` (candidat : "Catégorie" ; recruteur : "Recherche"), 2 = `thirdItemLabel` (candidat : "Portfolio" ; recruteur : "Publier"), 3 "Notification", 4 "Profil". Il n'y a plus d'item "Favoris". Dans `JobSeekerDashboard`, les items 1 à 4 font un `Navigator.push` vers leur écran puis remettent l'index actif à 0 au retour ; "Accueil" reste sur l'accueil.

### Recherche de comptes et profils consultables (candidat ↔ recruteur)

`AccountSearchRepository` (`lib/features/dashboard/data/account_search_repository.dart`) fait une recherche réelle en base, jamais de données mockées : `searchJobSeekers`/`searchEmployers` interrogent `job_seeker_profiles`/`employer_profiles` (+ compétences/expériences pour un candidat), "Aucun résultat" si rien ne correspond. L'historique de recherche (`search_history`, propre à chaque utilisateur et type de recherche) est enregistré à la fois sur validation clavier (`onSubmitted`) et à l'ouverture d'un profil depuis les résultats — sans ce second point, une recherche jamais "validée" au clavier avant de cliquer un résultat ne laissait aucune trace.

- `CandidateSearchScreen` (recruteur cherche un candidat) et `JobSearchScreen` (candidat cherche une entreprise) partagent la même structure : barre de recherche + historique, résultats sous forme de cartes. Aucun filtre au-delà du texte saisi (`showFilterButton: false` sur `SearchBarWidget`) — un filtre par localisation a été prototypé puis retiré à la demande, pas de trace dans le code actuel.
- Taper un résultat ouvre une vraie page de profil en lecture seule, pas une simple bottom sheet : `CandidateProfileViewScreen` (même identité visuelle que `JobProfileScreen` — bannière, avatar, "À propos", "Expérience", "Portfolio" (projets réalisés, `job_seeker_portfolio_projects`, liens cliquables), "Compétences", "Coordonnées") et `CompanyProfileViewScreen` (même identité que `EmployerProfileScreen`), tous deux dans `lib/features/dashboard/presentation/pages/`. Le bouton "Voir tout" de la section "Portfolio" de `CandidateProfileViewScreen` ouvre `CandidateFullPortfolioScreen` : le portfolio complet en une page façon site portfolio personnel (hero dégradé + identité, stats, À propos/Objectifs, Compétences, Expérience, Formation, Projets (grandes cartes), Certifications, Mes liens, Coordonnées) plutôt que la liste compacte de la page profil. Le candidat peut ouvrir exactement le même écran sur ses propres données depuis le bouton "Aperçu recruteur" de `PortfolioScreen` (`CandidateSearchResult.fromUser`, `isPreview: true` — affiche un bandeau "Aperçu" en plus, reste identique sinon) : jusqu'ici le rendu recruteur n'était visible que par un recruteur, jamais depuis le compte candidat lui-même. En mode aperçu, une icône palette dans le hero ouvre un choix de couleur (`PortfolioHeroTheme`, `lib/features/dashboard/presentation/widgets/portfolio_hero_theme.dart` — 6 thèmes : Violet/Bleu océan/Vert émeraude/Ambre/Rose/Graphite) qui change le dégradé du hero **et** les accents du reste de la page (badges, puces de compétences/technologies, icônes de timeline...) ainsi que ceux de `PortfolioScreen` (boutons, complétion, tuiles) ; persisté (`job_seeker_profiles.portfolio_theme_color`, migration v26→v27, `AuthService.updatePortfolioThemeColor`) et donc visible à l'identique par le recruteur (`CandidateSearchResult.portfolioThemeColor`, lu par `AccountSearchRepository`). Les 6 sous-écrans du Portfolio (`PortfolioAboutScreen`/`PortfolioSkillsScreen`/etc.) restent sur le violet par défaut, non couverts par ce thème pour l'instant.
- `EmployerDashboard` appelle `AccountSearchRepository.fetchAllJobSeekers()` pour "Candidats suggérés" : tous les candidats inscrits (profil visible), classés par correspondance locale (titre/compétences/localisation vs mots significatifs des titres d'offres publiées), les non-matchés en fin de liste sans score.

### Palette unique (bleu océan)

Le doublon violet/mauve (`OnboardingColors` vs `AppColors.primary`) est résolu : toute l'app est en bleu océan, avec les mêmes valeurs dans trois endroits — `OnboardingColors` (`lib/features/welcome/presentation/welcome_palette.dart`, onboarding), `DashboardColors` (`lib/features/dashboard/presentation/widgets/soft_ui.dart`, espaces candidat/recruteur) et `AppColors.primary*`. ### Écran d'accueil (welcome)

`lib/features/welcome/presentation/welcome_screen.dart` est un `StatefulWidget` avec un `AnimationController` (900ms, `easeOutCubic`) pilotant le fondu d'apparition du contenu. Fond en dégradé `OnboardingColors.bgTop → bgBottom` (défini dans `welcome_palette.dart`) avec des vagues violettes décoratives peintes en arrière-plan (`_BottomWavesPainter`). Layout à hauteur fixe, sans scroll, chaque bloc dimensionné en fraction de la hauteur disponible (`OnboardingLayout`) via `LayoutBuilder`, avec un facteur `scale` global (borné 0.82–1.12) qui adapte la typographie à la hauteur utile réelle : `_HeroSection` (image hero) → `_BrandBlock` (wordmark "JOEM" en dégradé navy→violet via `ShaderMask`, grilles de points décoratives, baseline "Job • Offres • ...") → `_TitleBlock` (les deux `_ActionCard` "Je suis recruteur" / "Je cherche un emploi") → `_Divider` → `_DescriptionBlock` → footer "Se connecter" (`_LoginFooter`).

Chaque `_ActionCard` affiche un titre (`_AutoFitText`, taille de base `19 * scale`, jusqu'à 2 lignes, rétrécit automatiquement plutôt que de déborder) et un sous-titre à deux lignes qui défilent en boucle façon ticker (`_RotatingSubtitle`, taille de base `12 * scale`, `maxLines: 1` — chaque ligne est donc forcée sur une seule ligne, `_AutoFitText` réduit la police jusqu'à ce qu'elle tienne plutôt que de passer à la ligne). Textes actuels : recruteur → "Publier des offres et trouvez" / "les meilleur talent" ; chercheur d'emploi → "Trouvez l'opportunité qui correspond" / "à votre profil". `_ActionCard` garde délibérément son propre effet de carte (fond blanc, ombre violette) plutôt que `core/widgets/glass_container.dart` — ce n'est pas un composant nommé `RoleSelectionCardWidget` séparé, ce nom ne correspond à rien dans le code actuel.
